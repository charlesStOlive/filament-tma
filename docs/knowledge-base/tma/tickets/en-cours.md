# En cours

**En cours**, le Support dit où il en est **sans rendre la main** au demandeur : il travaille sur la demande, et le
demandeur le suit.

## Passer en cours (le Support)

Sur une demande **Nouveau**, dans la zone **Nouveau message**, sous l'historique, **En cours** passe le ticket
**En cours**. Le message est facultatif : « Je regarde », « C'est corrigé en recette, je vérifie la production »… Il
s'ajoute à l'historique, avec le changement d'état. Si la demande n'avait pas encore de contact au Support, celui qui
la passe en cours le devient.

Le ticket arrive aussi **En cours** quand le demandeur répond à une question, renvoie une demande résolue, ou à la fin
d'une pause.

## Écrire pendant qu'il est en cours

Tant que le ticket est **En cours**, le même bouton **En cours** ajoute un message, sans changer l'état : un point
d'étape, une piste, ce qui reste à faire. Le texte est alors obligatoire.

Le demandeur, lui, n'écrit pas de message pendant ce temps : ce n'est pas son tour. Il ajoute des **notes**, sur un
message ou sur le ticket entier (voir [Les notes](#modal-tma.chronologie.notes)). Le dernier message du Support reste
donc le dernier du ticket : son auteur peut le **modifier** (au crayon, sous le message) pour le tenir à jour, plutôt
que d'en écrire un nouveau.

Chaque message peut dire **quel commit** porte le travail : voir [Le commit d'un message](#modal-tma.chronologie.commits).

## Ensuite

Quand le Support a besoin du demandeur, il **demande des précisions** ; quand le travail est fait, il le **marque comme
résolu**. Ces deux passages rendent la main au demandeur. Voir
[Demander des précisions](#modal-tma.tickets.question-reponse) et [Résolu](#modal-tma.tickets.validation).

## Qui est prévenu

Les destinataires principaux l'apprennent dans la **cloche** et dans le **bilan du matin**, pour information : rien ne
les attend, il n'y a pas de courriel. Voir [Les notifications](#modal-tma.notifications).
